# One primary Univer target per session

OpenWork sessions centered on Univer work will have at most one Primary Univer Target: one `.univer` file that supplies the default agent scope, composer context, and Univer worktree review context. Workspace files remain available as supporting context, references, or exchange files, but a session should not be equally bound to multiple `.univer` targets; users create or switch sessions when they want independent Univer task streams.

**Considered Options**

- Infer the target from the currently active artifact tab.
- Allow one session to be equally bound to multiple `.univer` targets.
- Bind a session to one Primary Univer Target while still allowing supporting workspace files.

**Consequences**

Session creation, task forking, composer context, and agent prompt context can all name one explicit `.univer` target. The binding belongs in durable server/session metadata, not only in local UI state, so sidebar grouping, prompt context, history, remote workspaces, and evals share the same source of truth. Sessions without durable target metadata should remain General Sessions; OpenWork should not infer a Primary Univer Target from message history, previously opened artifacts, or file mentions. Bound sessions should send minimal Univer Session Context to agents: the workspace-relative target path, display name, current task intent, and the rule that target changes require another session. OpenWork should not inject workspace file lists, unit inventories, or worktree snapshots into every prompt; agents should inspect target state through Univer CLI surfaces when needed. Read-only and analysis tasks should inspect the Primary Univer Target trunk and should not create a Session Univer Worktree or review state. A bound session composer defaults to continuing the current session; creating a new task on the same Primary Univer Target is an explicit action that creates another bound session rather than overloading the current composer. Creating that session should not eagerly create a Session Univer Worktree; worktrees are created when an agent actually performs a modifying task that needs review. When a modifying task creates a Univer worktree, or continues work in an existing session-owned worktree, that worktree should be associated with the owning Univer Task Session by persisting its worktree id in session metadata rather than becoming the target's global current worktree. The OpenWork runtime or Univer CLI Adapter should write `sessionUniverWorktreeId` automatically by observing new worktree creation results in the current bound session and verifying that the created worktree belongs to the session's Primary Univer Target; ordinary agent prompts should not be responsible for this metadata plumbing. Opening an existing worktree, viewing another session's review, or selecting a worktree in the Univer Surface should not overwrite the current session's Session Univer Worktree ownership. Sidebar state and Current Target Panel state should join that persisted `sessionUniverWorktreeId` to the live cowork snapshot; they should not infer ownership from worktree display names, commit messages, artifact history, chat messages, or agent progress text. Agent messages may explain progress, but they are not authoritative for marking a session working, ready, conflicted, merged, or discarded. If the persisted worktree id is absent from the snapshot, the session should show needs attention and the Current Target Panel should show Worktree missing/stale instead of silently selecting another worktree or falling back to working. The primary recovery actions should be Refresh status and Create new task from here; Manual reassociation should remain secondary or advanced. Refresh status should only reload live cowork or CLI state and recompute Session Review State; it should not mutate session metadata, clear `sessionUniverWorktreeId`, or invoke an agent. If the worktree reappears, the session should return to the derived working, ready, conflict, merged, or discarded state; otherwise it remains needs attention. Create new task from here should create a new Univer Task Session bound to the same Primary Univer Target without inheriting the old `sessionUniverWorktreeId`; it should retain only a read-only source reference to the original session. The new session may seed its title from `Retry: <original task title>` until the user's first new task prompt replaces it, and the original session should remain needs attention rather than being automatically marked Done. A session should have at most one active Session Univer Worktree at a time; the runtime and adapter should avoid creating a second active Univer worktree in a session that already owns one and should steer additional work toward a new task session. If a second active worktree is still created, OpenWork should not overwrite `sessionUniverWorktreeId`; it should mark the session as needing attention and make Split Into New Task the default recovery action. Manually choosing which worktree remains associated with the original session should remain a secondary or advanced recovery path because it is easier to mis-associate task history. After the session-owned worktree is merged or discarded, it becomes terminal: the session remains available for history and result inspection, but additional modifying work should use a new bound Univer Task Session instead of reusing the completed worktree. Once a non-empty session is bound, that binding should not switch inside the same session; moving to another `.univer` target means opening or creating another session. The main `Changes` entry point and default right-side Univer surface should follow the session's Primary Univer Target and, when applicable, the session-owned worktree rather than the most recently clicked `.univer` artifact. Cross-file Univer work remains possible, but it must treat non-primary files as supporting inputs or use a separate session for a separate primary task stream.
