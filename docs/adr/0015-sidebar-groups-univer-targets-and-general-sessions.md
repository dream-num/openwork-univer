# Sidebar groups Univer targets and general sessions

When a workspace contains `.univer` files, OpenWork's workspace sidebar will automatically discover Visible Univer Targets, treat each one as a Univer Target Hub, and show sessions bound to that file underneath it. Sessions without a Primary Univer Target remain available under General Sessions so OpenWork continues to support ordinary workspace-level agent work.

**Considered Options**

- Keep every session in one flat workspace task list.
- Replace the sidebar with a raw workspace file tree.
- Require users to manually add every `.univer` target before it appears in navigation.
- Group sessions by Primary Univer Target while keeping General Sessions for unbound work.

**Consequences**

The sidebar becomes the primary place to switch Univer work streams and discover review state: choosing another `.univer` target means choosing or creating a different session, not mutating the current session's Primary Univer Target. A Univer Target Hub should show only compact target metadata, such as file name, unit count, and actionable session count; it should not expand into a unit tree. Session rows under a Univer Target Hub should expose one primary Session Review State, such as working, ready for review, conflict, needs attention, merged, or discarded, because each Session Univer Worktree belongs to the session/task that created it. OpenWork should derive these state chips from the persisted `sessionUniverWorktreeId` joined with live cowork or CLI state, not from agent text claims. `Needs attention` covers exceptional states such as a missing persisted worktree or multiple active worktrees in one session. Session row titles should describe the task, using the user's first task prompt or an agent-generated short title; review state belongs in the status chip and should not replace or rewrite the task title. For multiple-worktree attention states, the selected session should present Split Into New Task as the primary recovery action and manual reassociation as a secondary option. A row may include a lightweight count, but it should not expose unit diffs, conflict details, or merge/discard actions; those belong inside the selected session's Current Target Panel or Univer Surface. A target hub may show an aggregate compact count, but the concrete reviewable items are sessions, not a hidden target-level queue. Sessions under a target should sort by actionability first: ready for review, conflict, and needs-attention sessions appear before working sessions, followed by ordinary or historical sessions; rows with the same state sort by recent activity. Merged and discarded sessions should collapse into a `Done` group by default so a long-lived `.univer` target stays focused on current work while preserving access to completed task history. Done sessions remain openable for history and result inspection: merged sessions should default to the current target trunk result, while discarded sessions should default to a read-only discarded worktree diff or summary. Done sessions should not continue modifying the completed Session Univer Worktree; if the user submits another modifying task from a Done session, OpenWork should prompt to create a new bound task session for the same Primary Univer Target. The primary click on a Univer Target Hub should open the highest-priority non-`Done` task session for that target: ready for review, conflict, or needs attention first, then working, then an ordinary planning task. If no non-`Done` task session exists, OpenWork should open or create the target's single Target Overview Session. The Target Overview Session is reused for hub entry, does not enter `Done`, does not count as a new task, and should not render as an ordinary `Untitled chat` row under the target. Opening the Target Overview Session should default the right-side content to the Univer Surface for the target rather than a blank chat-first view, because the user entered through the `.univer` file. If the user submits a task from the Target Overview Session, OpenWork should create and switch to a new bound task session instead of storing long-running task chat history in the overview. New task sessions are the rows that appear under the target with task titles; the `+` action is the explicit way to create one. Choosing `+` should create an empty task session already bound to that Primary Univer Target, select it, and focus the composer with a target-aware placeholder rather than a prefilled prompt; the user's first submitted task prompt becomes the task title seed and agent starting point. Expanding and collapsing the hub should use a separate disclosure control. Target discovery should filter hidden runtime data, dependency directories, generated caches, and other non-user-facing `.univer` artifacts. Workspace Files remains the ordinary filesystem browser; it may open or bind `.univer` targets, but it does not replace the target/session navigation model.
