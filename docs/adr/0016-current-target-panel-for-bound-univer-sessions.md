# Current target panel for bound Univer sessions

For sessions bound to a Primary Univer Target, OpenWork will replace the composer-level Files popover with a Current Target Panel. The panel centers the session on the bound `.univer` target by showing target identity, target-level unit status, and the current session's Session Univer Worktree when one exists; Workspace Files remains available for General Sessions and other unbound workspace work.

**Considered Options**

- Keep Files and Changes as separate composer toolbar entries for every session.
- Remove file context entirely from the composer area.
- Use a Current Target Panel for bound Univer sessions while keeping Workspace Files for General Sessions.

**Consequences**

Bound Univer sessions stay in the Univer target mental model instead of returning users to a directory workspace model. The user-facing toolbar entry should use the target file name and a compact status, such as the `.univer` display name plus the current session's review or worktree state, rather than exposing "Current Target" as primary UI text. The panel's top-level sections should be `Units` and `Active task`, so users see the target contents and the current session's in-progress or ready-for-review work without learning implementation-first labels such as "main worktree" or "active changes". `Units` shows target trunk unit status. `Active task` is session-scoped; before the session has a Session Univer Worktree, it should show an explicit no-changes-in-this-session state and should not show ready/review controls. If the session has a persisted worktree id but that worktree is missing from live state, `Active task` should show Worktree missing/stale and should not fall back to another worktree for the same target. That state should present Refresh status and Create new task from here as the primary actions, with Manual reassociation in a secondary or advanced menu. Refresh status should reload cowork or CLI state and recompute the panel and sidebar state without changing metadata or invoking an agent; if the worktree reappears, the panel leaves Worktree missing/stale and renders the derived state, otherwise it stays needs attention. Choosing Create new task from here should create and select a new task session bound to the same Primary Univer Target, preserve only a read-only reference back to the source session, and seed the title as `Retry: <original task title>` unless the user's first new prompt replaces it. Once a Session Univer Worktree exists, `Active task` shows the current session's worktree state, changed units, and, if that worktree is ready, review details and merge/discard actions. After merge or discard, `Active task` should become a read-only completion summary for that session-owned worktree; further modification should route through a new bound task session rather than reusing the completed worktree. OpenWork should not introduce separate review, progress, and Univer surfaces for these states. State-specific defaults should instead select the right Univer Content Scope in the existing Univer Surface: current version for overview or planning, original worktree changes for working tasks, original changes or merge preview for ready review tasks, current trunk result for merged sessions, and a read-only discarded worktree diff or summary for discarded sessions. Terminal states should not default to an editable worktree scope. Cross-session review discovery belongs in the sidebar session rows described by ADR 0015, not in a target-level `Ready for review` list inside the panel. `Changes` becomes a state area inside Current Target rather than a separate primary entry point. General Sessions still need Workspace Files because they have no Primary Univer Target or sidebar target hub to provide file context.
